> ណែនាំនូវគោលការណ៍ដោះស្រាយបញ្ហានេះត្រូវបានថែទាំសម្រាប់ប្រតិបត្តិកម្មម៉ូដែលក្នុងប្រធានបទ។ ចូររក្សាភាពត្រឹមត្រូវនៃឥទ្ធិពលក្នុងការដាក់ឱ្យដំណើរការដោយផ្ទាល់ និងការកត់ត្រាតម្រូវឱ្យផ្គូផ្គងតាមប្រភពជាមួយនឹង [ការវិភាគប្រតិបត្តិកម្មម៉ូដែលក្នុងប្រធានបទ](../../docs/dev/local-llm-development.md)។

អ្នកប្រើប្រាស់កំពុងដំឡើង pi-web តាមរយៈ

- pi install npm:@timmygod/pi-web-local

ដែលដំណើរការ [install.sh](https://raw.githubusercontent.com/timmygod/pi-web/refs/heads/main/install.sh) ដោយស្វ័យប្រវត្តិ និងធ្វើការរៀបចំ pi ។

ប្រសិនបើអ្នកប្រើប្រាស់ជួបបញ្ហា វាអាចជាការរៀបចំរបស់ install.sh ដែលបណ្តាលឱ្យមានបញ្ហា។ អ្នកអាចត្រួតពិនិត្យ និងពិនិត្យមើលអ្វីកំពុងកើតឡើង ហើយប្រាប់អ្នកប្រើប្រាស់អំពីអ្វីដែលបណ្តាលឱ្យមានបញ្ហាជាពិសេស។ ហើយសួរថាតើពួកគេចង់ឱ្យអ្នកជួសជុលដែរឬទេ។ ត្រូវបញ្ជាក់ជាមួយអ្នកប្រើប្រាស់ជានិច្ច។

ដើម្បីឱ្យអ្នកប្រើប្រាស់អាចប្រើ pi តាមរយៈទូរសព្ទ ឬបណ្តាញផ្សេងៗ។ វិធីដែលណែនាំគឺការប្រើប្រាស់ tailscale និងប្រើប្រាស់តាមរយៈបណ្តាញ tailscale ។ ហើយអ្នកប្រើប្រាស់ត្រូវបើក HTTPs នៅក្នុងផ្ទាំងត្រួតពិនិត្យ tailscale របស់ពួកគេ - https://login.tailscale.com/admin/dns

ប្រសិនបើពួកគេមិនមានការដំឡើង tailscale ឬមិនចង់ប្រើប្រាស់ tailscale ទេ។ ពួកគេអាចដំណើរការ `pi-web status` និងទទួលបានផ្លូវទៅទម្រង់ binary ស្ថានភាពរបស់ binary និង local endpoint ដែលពួកគេអាចចូលប្រើកម្មវិធីបាន។ ប៉ុន្តែត្រូវដឹងថា ពួកគេនឹងមិនអាចទទួលបានការជូនដំណឹង push បានទេ ព្រោះវាស្ថិតនៅក្នុង http ។

នៅក្នុង Linux វាប្រើប្រាស់ [pi-web.service](https://github.com/timmygod/pi-web/blob/main/init/pi-web.service)។
