# ហេតុអ្វី pi-web?

ខ្ញុំញៀននឹង Claude Code បន្តិចហើយ។ ខ្ញុំតែងតែប្រើវាជានិច្ច។ បើខ្ញុំមិនបានអង្គុយនៅមុខកុំព្យូទ័រទេ ខ្ញុំកំពុងគិតអំពីវា។ ខ្ញុំមានអារម្មណ៍ថាខ្ញុំមិនបានដុត tokens គ្រប់គ្រាន់ទេ។ វាជាសម័យដើមរបស់ Claude Code។ ហើយខ្ញុំកំពុងគិតថា ហេតុអ្វីខ្ញុំមិនអាចបន្តពីទូរស័ព្ទរបស់ខ្ញុំ? ខ្ញុំបានដំឡើង Termius ហើយខ្ញុំមិនសូវចូលចិត្តវាទេ។

ខ្ញុំចាប់ផ្តើមបង្កើតដោយខ្លួនឯង ហើយឈប់នៅពេល Claude បានបង្ហាញកម្មវិធីទូរស័ព្ទ Claude Code របស់ពួកគេ។

បន្ទាប់មកខ្ញុំមានបញ្ហាឌីសឆ្អឹងខ្នងរបើក ហើយខ្ញុំមិនអាចធ្វើអ្វីបានច្រើនទេ។ ពេលវេលាកន្លងទៅ ហើយខ្ញុំមានអារម្មណ៍ថាបានជាសះស្បើយបន្តិច ហើយខ្ញុំចង់បន្តគម្រោង Claude Code តាមរយៈ web/pwa របស់ខ្ញុំ។

បន្ទាប់មក Claude Code បានចាប់ផ្តើមហាមឃាត់ការប្រើប្រាស់ក្រៅពី harness របស់ពួកគេ។ ហើយខ្ញុំមានអារម្មណ៍ថាវាមិនសមនឹងការខំប្រឹងទេ។

បន្ទាប់មកខ្ញុំបានរកឃើញ pi.dev ហើយបានស្វែងយល់បន្តិចបន្តួច ប៉ុន្តែមិនទាន់បានស្វែងយល់ស៊ីជម្រៅទេ។ ខ្ញុំបានអានអំពីវា មើលវីដេអូអំពីវា ហើយសម្រេចចិត្តសាកល្បងពេញលេញ ហើយឥឡូវនេះខ្ញុំចូលចិត្ត pi ទាំងស្រុង។

ដោយសារវាជា open source ខ្ញុំមានអារម្មណ៍ថាវាសមនឹងការសាងសង់សម្រាប់។ ខ្ញុំក៏មានជម្រើស provider ផ្សេងៗគ្នាផងដែរ។ ខ្ញុំក៏មានអារម្មណ៍ថាការពឹងផ្អែកលើ provider/model តែមួយដូចជា Anthropic/Claude គឺមិនមាននិរន្តរភាពទេ។

ដូច្នេះខ្ញុំកំពុងសាងសង់វានៅទីនេះ។

## ហេតុអ្វីបានជាគំរូក្នុងស្រុកត្រូវការប្រវត្តិរូបប្រតិបត្តិការខុសគ្នា

បទពិសោធន៍ pi-web ដើមគឺជាមូលដ្ឋានគ្រឹះដ៏ល្អឥតខ្ចោះ ប៉ុន្តែការសន្និដ្ឋានក្នុងស្រុកមានរបៀបបរាជ័យខុសគ្នាពីគំរូដែលបានផ្ទុកឡើងជាទូទៅ។ គំរូក្នុងស្រុកអាចយឺតយ៉ាវយ៉ាងខ្លាំងនៅពេលបរិបទកើនឡើង ចែករំលែកអនុស្សាវរីយ៍មានកំណត់ជាមួយផ្នែកផ្សេងទៀតនៃម៉ាស៊ីន ឈប់បន្ទាប់ពីផលិតតែការគិតប៉ុណ្ណោះ ឬបាត់បង់ការដំណើរការវែងដោយសារកំហុសការដឹកជញ្ជូនក្នុងស្រុកបណ្តោះអាសន្ន។ ការព្យាបាលករណីទាំងនោះដូចគ្នាបេះបិទទៅនឹងកំហុស cloud ធ្វើឱ្យ UI មើលទៅស៊ីសង្វាក់គ្នា ខណៈដែលសម័យកាលពិតប្រាកដនៅតែងាយរងគ្រោះ។

កំណែនេះខិតជិតបញ្ហាតាមស្រទាប់៖

1. **រក្សា upstream ជាមុនសិន។** ឥរិយាបថ UI និងសម័យកាលរួមបន្តមកពី pi-web; ការផ្លាស់ប្តូរក្នុងស្រុកត្រូវបានបំបែកនៅពីក្រោយ Local Mode ដែលមានប្រសិទ្ធភាព។
2. **ការពារមុនពេលស្តារឡើងវិញ។** ព្រំដែនបរិបទ 65% ផ្អែកលើភាគរយត្រូវបានអនុវត្តមុនការហៅអ្នកផ្តល់សេវាបន្ទាប់ រួមទាំងការហៅនៅក្នុងរង្វិលជុំឧបករណ៍វែង។
3. **ស្តារឡើងវិញតែនៅពេលមានភស្តុតាង។** ការបន្តស្វ័យប្រវត្តិត្រូវបានកំណត់តែសម្រាប់ហេតុការណ៍បរិបទ ការដឹកជញ្ជូន និងគិតតែប៉ុណ្ណោះដែលត្រូវបានទទួលស្គាល់ មិនមែនកំហុសផ្ទៀងផ្ទាត់ កូតា ឬកំហុសអ្នកផ្តល់សេវាដោយចៃដន្យទេ។
4. **កំណត់សកម្មភាពស្វ័យប្រវត្តិគ្រប់យ៉ាង។** ហេតុការណ៍ស្តារឡើងវិញត្រូវបានកម្ចាត់ភាពស្ទួន វឌ្ឍនភាពត្រូវបានទាមទារមុនការសង្គ្រោះម្តងទៀត ហើយការចាប់ផ្តើមពិចារណាតិចបំផុតនឹងសម័យកាល Local ដែលសកម្មថ្មីៗមួយ។
5. **រក្សាផ្លូវចេញដោយដៃ។** Force Compact សង្ខេបជំនួសឱ្យការលុបប្រវត្តិ ដូច្នេះអ្នកប្រើប្រាស់អាចសង្គ្រោះសម័យកាលដោយមិនបន្លំថាបរិបទមិនធ្លាប់មាន។
6. **ការពារភាពស៊ីសង្វាក់គ្នា cloud។** Cloud Mode រក្សាអត្ថន័យ និងការគ្រប់គ្រង upstream; ការបង្កើនប្រសិទ្ធភាពគំរូក្នុងស្រុកមិនកំណត់និយមន័យសម័យកាល cloud ឡើងវិញដោយស្ងាត់ៗទេ។

នោះគឺជាភាពខុសគ្នាពិតប្រាកដក្នុង fork នេះ៖ វាព្យាបាលការសន្និដ្ឋានក្នុងស្រុកជាបរិស្ថានប្រតិបត្តិការដាច់ដោយឡែក មិនមែនគ្រាន់តែជាឈ្មោះគំរូមួយទៀតនៅក្នុងបន្ទះទម្លាក់ចុះទេ។
