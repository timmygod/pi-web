# ทำไมต้อง pi-web?

ผมค่อนข้างติด Claude Code ครับ ผมใช้มันตลอดเวลา ถ้าไม่ได้นั่งอยู่หน้าคอมพิวเตอร์ ผมก็คิดถึงมัน ผมรู้สึกเหมือนว่าใช้ tokens ไม่มากพอ มันเป็นช่วงแรก ๆ ของ Claude Code และผมก็คิดว่า ทำไมผมถึงกลับมาใช้งานต่อจากมือถือไม่ได้? ผมลองตั้งค่า Termius แล้วก็ไม่ค่อยชอบ

ผมเริ่มสร้างของตัวเองและหยุดไปเมื่อ Claude เปิดตัวแอปมือถือ Claude Code

จากนั้นผมก็หมอนรองกระดูกเคลื่อนและทำอะไรไม่ค่อยได้เลย เวลาผ่านไปผมรู้สึกฟื้นตัวขึ้นมาบ้างและอยากจะทำโปรเจกต์ Claude Code ผ่านเว็บ/pwa ต่อ

จากนั้น Claude Code ก็เริ่มแบนการใช้งานนอก harness ของตัวเอง และผมรู้สึกว่ามันไม่คุ้มค่า

จากนั้นผมก็เจอ pi.dev และลองสำรวจดูบ้างแต่ยังไม่ได้ลงลึกจริง ๆ ผมอ่านเกี่ยวกับมัน ดูวิดีโอเกี่ยวกับมัน และตัดสินใจลองใช้อย่างจริงจัง ตอนนี้ผมหลงใหล pi เต็มตัวแล้ว

เพราะว่ามันเป็นโอเพนซอร์ส ผมรู้สึกว่ามันคุ้มค่าที่จะสร้างให้ ผมมีตัวเลือก provider ที่หลากหลายด้วย ผมยังรู้สึกว่าการพึ่งพา provider/model เดียวอย่าง Anthropic/Claude นั้นไม่ยั่งยืน

ผมเลยกำลังสร้างมันอยู่ที่นี่

## เหตุใดโมเดลท้องถิ่นจึงต้องการโปรไฟล์การทำงานที่แตกต่าง

ประสบการณ์ pi-web เดิมเป็นรากฐานที่ยอดเยี่ยม แต่การอนุมานในเครื่องมีโหมดความล้มเหลวที่แตกต่างจากโมเดลที่โฮสต์ทั่วไป โมเดลท้องถิ่นอาจช้าลงอย่างมากเมื่อบริบทขยายขึ้น แบ่งปันหน่วยความจำที่จำกัดกับส่วนอื่นของเครื่อง หยุดหลังจากสร้างเฉพาะการให้เหตุผล หรือสูญเสียการทำงานที่ยาวนานเนื่องจากความล้มเหลวในการส่งข้อมูลท้องถิ่นชั่วคราว การจัดการกรณีเหล่านั้นเหมือนกับความล้มเหลวบนคลาวด์ทำให้ UI ดูเข้ากันได้ ในขณะที่เซสชันจริงยังคงเปราะบาง

เวอร์ชันนี้เข้าใกล้ปัญหาเป็นชั้นๆ:

1. **รักษา upstream ก่อน** UI ที่ใช้ร่วมกันและพฤติกรรมเซสชันยังคงมาจาก pi-web; การเปลี่ยนแปลงท้องถิ่นถูกแยกไว้เบื้องหลัง Local Mode ที่มีประสิทธิภาพ
2. **ป้องกันก่อนกู้คืน** ขอบเขตบริบท 65% ที่อิงตามเปอร์เซ็นต์ถูกบังคับใช้ก่อนการเรียกผู้ให้บริการในภายหลัง รวมถึงการเรียกภายในลูปเครื่องมือที่ยาว
3. **กู้คืนเฉพาะเมื่อมีหลักฐาน** การดำเนินการต่ออัตโนมัติจำกัดเฉพาะเหตุการณ์บริบท การส่งข้อมูล และการคิดเท่านั้นที่รู้จัก ไม่ใช่ข้อผิดพลาดการตรวจสอบสิทธิ์ โควตา หรือข้อผิดพลาดของผู้ให้บริการแบบสุ่ม
4. **จำกัดการกระทำอัตโนมัติทุกประการ** เหตุการณ์การกู้คืนถูกกำจัดซ้ำ ความคืบหน้าจำเป็นก่อนการช่วยเหลืออื่น และการเริ่มต้นพิจารณาเซสชัน Local ที่ใช้งานล่าสุดอย่างน้อยหนึ่งครั้ง
5. **คงทางออกแบบแมนนวล** Force Compact สรุปแทนที่จะลบประวัติ เพื่อให้ผู้ใช้สามารถกู้เซสชันได้โดยไม่ต้องแกล้งทำว่าบริบทไม่เคยมีอยู่
6. **ปกป้องความเข้ากันได้กับคลาวด์** Cloud Mode คงความหมายและการควบคุม upstream ไว้; การเพิ่มประสิทธิภาพโมเดลท้องถิ่นไม่ได้นิยามเซสชันคลาวด์ใหม่อย่างเงียบๆ

นั่นคือความแตกต่างที่แท้จริงใน fork นี้: มันถือว่าการอนุมานในเครื่องเป็นสภาพแวดล้อมการทำงานที่แยกต่างหาก ไม่ใช่แค่ชื่อโมเดลอื่นในเมนูแบบเลื่อนลง
